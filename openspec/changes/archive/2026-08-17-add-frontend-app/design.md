## Context

В репозитории есть только API-контракт `spec/main.tsp` (TypeSpec), компилируемый в OpenAPI (`spec/tsp-output`). Бэкенд на Go планируется отдельно; `frontend/` отсутствует. AGENTS.md фиксирует монорепозиторий: `frontend/` — React 19, `backend/` — Go, команды через корневой `Makefile`. Мотивация и объём — см. proposal.md; требования — см. specs/frontend-app/spec.md.

## Goals / Non-Goals

**Goals:**

- Отдельное SPA на Vite + React 19 + TypeScript, работающее с бэкендом только по OpenAPI-контракту.
- Типобезопасный API-клиент, генерируемый из контракта, — единственная точка доступа к API.
- Разработка без бэкенда через Prism (mock по контракту) и с бэкендом через dev-прокси Vite.
- UI на shadcn/ui + Tailwind CSS; shadcn MCP Server настроен для агентов.

**Non-Goals:**

- Авторизация и разграничение доступа (в API её нет — MVP).
- Изменение контракта `spec/main.tsp` или бэкенда.
- SSR/SEO, мобильное приложение, уведомления гостя (email/SMS).
- Отображение времени в локальной таймзоне гостя (контракт работает в UTC — отображаем UTC с явной пометкой).

## Decisions

### 1. Vite + React 19 + TypeScript

Быстрый dev-сервер и сборка из коробки, соответствует AGENTS.md (React 19) и запросу. Альтернативы (Next.js, Remix) избыточны: SSR не нужен, а Next добавил бы серверный рантайм, нарушающий принцип «отдельно запущенный бэкенд».

### 2. shadcn/ui + Tailwind CSS, без Mantine

shadcn/ui копирует компоненты в проект — полный контроль над разметкой и стилями, что важно для долгой поддержки; выбрано пользователем. Mantine исключаем, чтобы не тащить вторую стилевую систему. shadcn MCP Server регистрируется в конфигурации агентов (`.opencode/`) для работы с компонентами (поиск, добавление блоков).

### 3. API-клиент генерируется из OpenAPI

Контракт компилируется из `spec/main.tsp` в OpenAPI; из него генерируются TypeScript-типы и клиент (openapi-typescript + openapi-fetch либо Orval — финальный выбор на этапе задач, предпочтение минимальному рантайму: openapi-typescript + openapi-fetch). Альтернатива — рукописный клиент: отклонена, рано или поздно разойдётся с контрактом. Генерация — шаг сборки/скрипт, артефакт коммитится или пересобирается перед lint/test/build.

### 4. Адрес API — через переменные окружения, dev — через прокси или Prism

Базовый URL API задаётся `VITE_API_BASE_URL` (по умолчанию `/api` через dev-прокси Vite на `localhost:8080`, что снимает вопрос CORS). Mock-режим: Prism поднимается над OpenAPI-файлом (`prism mock`), фронтенд направляется на него той же переменной окружения — npm-скрипт `dev:mock` поднимает Prism и Vite вместе.

### 5. Маршрутизация и структура страниц

React Router, плоские маршруты:

- `/` — список типов событий (гость).
- `/book/:eventTypeId` — слоты типа события и форма бронирования (гость).
- `/admin/event-types` — CRUD типов событий (владелец).
- `/admin/schedule` — расписание по умолчанию (владелец).
- `/admin/bookings` — предстоящие брони (владелец).

Админ-раздел отделён только навигационно — авторизации нет, как и в API.

### 6. Доступ к данным — TanStack Query

Кэширование, состояния загрузки/ошибок, инвалидация после мутаций (создание брони → обновление слотов и списка броней). Альтернатива (Redux + ручные thunk) избыточна для CRUD-интерфейса.

### 7. Обработка ошибок по кодам контракта

Слой API-клиента разбирает тела ошибок 400/404/409 и сопоставляет `code` с сообщениями UI (`SLOT_BUSY` → «слот занят, выберите другое время» + инвалидация слотов; `CONTACT_REQUIRED` → подсветка полей контактов и т.д.). Неизвестный код → общее сообщение с текстом `message` из ответа.

### 8. Время — строго UTC

Все даты/время отображаются и вводятся в UTC с явной пометкой «UTC», в формате ISO 8601 к бэкенду. Локализация таймзон — отдельное будущее изменение, чтобы не расходиться с контрактом (рабочие часы интерпретируются в UTC).

## Risks / Trade-offs

- [Бэкенд ещё не реализован — проверить интеграцию с реальным сервером невозможно] → разработка и ручные сценарии против Prism; финальная ручная проверка против реального бэкенда остаётся в задачах как отдельный шаг после его появления.
- [Prism отдаёт примеры/сгенерированные данные, не покрывающие коды ошибок и динамику слотов] → в OpenAPI при необходимости добавляются examples; сценарии ошибок проверяются unit-тестами обработчиков ошибок, а не только mock-ом.
- [Расхождение сгенерированного клиента и контракта при правках spec] → генерация клиента включена в скрипты и цели Makefile; контракт меняется только через отдельный change.
- [shadcn/ui требует ручной установки каждого компонента] → принимаем: фиксируем список используемых компонентов в задачах; MCP-сервер ускоряет добавление новых.
- [CORS при работе против реального бэкенда вне dev-прокси] → в dev используем прокси Vite; требование CORS-заголовков к бэкенду зафиксировано в proposal (Impact) и реализуется на стороне бэкенда.

## Migration Plan

Неприменимо — новая часть приложения, существующий код не затрагивается. Откат = удаление директории `frontend/`.
