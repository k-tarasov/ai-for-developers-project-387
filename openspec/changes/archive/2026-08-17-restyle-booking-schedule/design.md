## Context

Страница `frontend/src/pages/book-page.tsx` сейчас рендерит все слоты плоским списком по дням (`groupSlotsByDay`) с горизонтальным переносом кнопок. В проекте уже есть готовый компонент календаря `Calendar` (`frontend/src/components/ui/calendar.tsx`) на базе `react-day-picker`, но он нигде в гостевом потоке не используется. Моки/реальный `useSlots` возвращают `{ slots, windowStartsOn, windowEndsOn }` — эти данные достаточны для нового макета без изменения API.

## Goals / Non-Goals

**Goals:**
- Заменить плоский список дней на двухколоночный макет: календарь слева, колонка слотов выбранного дня справа.
- Переиспользовать существующий `Calendar` без добавления новых зависимостей.
- Сохранить всю логику бронирования и контракт API.

**Non-Goals:**
- Не менять форму бронирования, валидацию, подтверждение, обработку `SLOT_BUSY`.
- Не менять бэкенд, схему данных и форматы API.
- Не добавлять мульти-выбор дней или выбор нескольких слотов.

## Decisions

- **Переиспользование `Calendar`.** Используем `mode="single"` с пропсами `selected`, `onSelect`, `defaultMonth={windowStartsOn}`, `disabled` и локализацией. Альтернатива — писать свой грид дней: отклонена, чтобы не дублировать доступный компонент и стили.
- **Множество доступных дней.** Из `slots` через `groupSlotsByDay` строим `Set` из `utcDayKey`. Дни вне этого множества (и вне окна `windowStartsOn`–`windowEndsOn`) передаём в `disabled` как массив матчеров `[{ before }, { after }, (date) => !available.has(dayKey(date)) ]`.
- **Состояние выбранного дня.** Добавляем `selectedDay: Date | undefined`, инициализируем первым доступным днём из множества (как в cal.com — день预выбран сразу). При выборе дня фильтруем `slots` по `utcDayKey` этого дня и показываем вертикальной колонкой. Смена дня сбрасывает `selectedSlot`, если он не принадлежит новому дню (через `useEffect` или при `onSelect`).
- **Раскладка.** Три колонки через `grid gap-4 md:grid-cols-3` (на мобильных — складываются друг под друга): (1) карточка с информацией о событии (название, длительность, окно записи UTC), (2) календарь, (3) колонка слотов.
- **Календарь с месяцами/годам.** Передаём в `Calendar` `captionLayout="dropdown"` (выпадающие списки месяца и года) вместо `label`, чтобы гость мог переключать месяцы и годы; `defaultMonth={windowStartsOn}` открывает текущий/нужный месяц. Дни вне окна и без слотов остаются `disabled`.
- **Независимая прокрутка колонки слотов.** Третья колонка получает ограниченную высоту (например, `max-h-[70vh]` или высота вьюпорта) с `overflow-y-auto`, чтобы прокручивались только слоты, а страница целиком не сдвигалась. Заголовок выбранного дня (день недели + число + «UTC») остаётся закреплённым над прокручиваемой областью.
- **Часовые пояса.** Календарь оперирует `Date`; слоты и метки времени — строго UTC (контракт API). Чтобы избежать рассинхрона «день календаря ≠ день слота», множество доступных дней и матчер `disabled` сравниваются по `utcDayKey` (UTC-полночь), а не по локальному дню. Отображаемое время слотов остаётся UTC с пометкой.
- **Новый компонент.** При желании вынести колонку слотов в `frontend/src/components/slot-column.tsx`; решение за исполнителем, логика небольшая и допустима inline в `book-page`.

## Risks / Trade-offs

- [Рассинхрон дней из-за часовых поясов] → Сравнение доступных дней и матчер `disabled` ведётся по `utcDayKey` (UTC), метки времени UTC, как и сейчас.
- [Дни вне окна остаются кликабельными в навигации календаря] → `disabled` блокирует выбор дней вне `windowStartsOn`–`windowEndsOn` и без слотов.
- [Сценарии тестов полагаются на плоский список] → `book-page.test.tsx` адаптируется: сначала выбор дня в календаре, затем появление слотов (см. tasks).
